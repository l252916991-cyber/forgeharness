## 审查覆盖

- 架构：协作定义编译为现有 R2 模型节点；没有第二套状态、预算或权限引擎。
- 正确性：稳定任务 ID、专家重复分配、结果在下游前校验、对账时再次校验、实际用量保留。
- 恢复：已有结果复用、发送前持久化未知状态、进程退出窗口、取消后的未知预留。
- 安全边界：空工具目录、空 registry 与拒绝策略；宿主认证和资源重验；节点材料按分配隔离；
  公共 root task 对所有专家可见；本地 schema 引用禁止远程解析；凭据定义拒绝。
- 依赖：仅复用已有 Pydantic/JSON Schema；新示例进入 sdist、最小 wheel 的执行门禁。
- 文档与能力声明：单机串行、一次模型决策、固定图；真实质量、并行、自主循环和写隔离另验。

## 已确认发现

| ID | 严重性 | 状态 | 发现与处理 |
|---|---|---|---|
| MA-001 | high | fixed | 新增 output schema 的首次实现仅覆盖普通模型结算，R2 reconcile 直接结算会绕过校验。回归 `test_reconciliation_cannot_bypass_result_schema` 首次失败；现在正常结算和对账共用同一校验函数，非法回执保留用量并使节点失败。 |

| MA-003 | medium | fixed | 底层 JSON 解析函数原本依赖上游先校验 schema；独立调用可能触发外部引用解析。函数自身现在再次拒绝远程引用，回归确认拒绝发生在解析之前；同时拒绝浮点溢出产生的非有限数。 |
| MA-004 | medium | fixed | Python 调用者可传 None 绕开必填 guard 的类型注解。协作入口现显式要求两个 callable，并重验预算对象；无 guard 时在创建状态目录前拒绝。 |

## 接受的剩余边界

1. 节点顺序执行；不声称并行延迟收益。
2. 专家是一次 final-only 决策；没有自主工具循环和独立可恢复 child run。
3. 只验证输出结构、任务归属和证据引用身份；不判断引用语义支持或专业正确性。
4. 实现和工程门禁使用脚本模型与合成回执；token 仅用于计账断言，不能当作真实成本。
5. 继续继承 R2 的单机 POSIX/SQLite、owner fencing、至少一次 outbox、未知结果不盲重放等边界。
6. 模型用量来自 provider；预算预检采用现有启发式估算，不能推出真实 tokenizer 上界。
