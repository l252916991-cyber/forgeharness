## 实现与验证边界

串行托管使用现有 AgentRuntime，PG 保存唯一控制权和完整物理事实。可信应用注册绑定
原 owner、部署、模型配置、工具和预算；普通成员、审批人和执行服务分离。发送闭包单次，
unknown 不重发或记零，旧 epoch 只能追加已证实事实；终态重新核对完整费用和证据。
策略拒绝使用逻辑用量账本，真实结果超额也保留成本并明确结束为 EXHAUSTED。

上下文、缓存标记、准备请求、实际 HTTP 字节和证据相互核对；响应体在解析前受限，包含
完整请求期限。文件操作、安装和发布 staging 使用 POSIX descriptor/no-follow，执行子进程
输出持续有界读取，容器池容量与取消/清理显式管理。任务板恢复仅使用已接受的成功事实。

候选门禁要求源码及干净副本分别通过格式、类型、全量核心测试、真实 PostgreSQL、
联合覆盖率及纯分支 85% 门槛、业务/安全开发契约、浏览器竞态、框架组合、依赖审计、
wheel/sdist 文件及摘要绑定、基础包和独立 Web/Cloud 消费者。开发测试不会拼接成冻结资格。
封装出来的单位费用不是人民币价格；合成业务和 loopback 模型不是真实客户业务或生产供应商。

## 工程候选接受的残余风险

- 技能升级跨两次 rename，硬崩溃可留下隐藏备份，需人工检查恢复；不支持零停机原子升级。
- POSIX 文件约束和命令策略不是 OS sandbox。同 UID 恶意进程、特权挂载/移动和任意主机
  命令需要宿主进程隔离；单链接检查不能防止复制秘密内容。
- 容器测试使用受控 runner 与真实本机子进程；未运行真实 Docker daemon，未验内核/cgroup、
  网络、镜像用户和 daemon 故障恢复，不能声称这些生产隔离已获验证。
- 单个 spill 上限 16MiB，模型响应默认 8MiB/最大 16MiB，发行物每个 64MiB、资格文件 16MiB。
  总磁盘/租户累计额度和资料保留删除尚未完成；拒绝压缩模型响应是明确的兼容性约束。
- 文件搜索为 literal，跳过隐藏/二进制/大文件，不读取 ignore 文件。超大单目录排序无独立
  内存配额；宿主必须约束工作区规模。
- 自定义 model preparation 必须确定性重建同一规范输入；随机 nonce/timestamp 会 fail closed，
  不能据此重新发送。已部署版本和原 checkpoint 不作隐式升级。
- schema1→2 要求管理员 drain 原 worker，并显式执行迁移和重授运行权限。没有生产数据库
  迁移/回滚或跨区域灾备演练的证据。
- GitHub 远端 environment/OIDC/分支权限、Action tag 供应链设置和实际 PyPI 发布未在本机验证。
  发布工作流强制先完整资格，再按摘要复制同次 wheel/sdist；本批没有触发发布。
- 可选框架依赖历史 NLTK advisory 只在完整依赖审计实际成功时沿用既有精确例外；
  不允许因新告警失败自动扩大豁免范围。
