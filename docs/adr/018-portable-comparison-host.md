# ADR 018：将框架原生能力与共同宿主契约分开验证

日期：2026-10-16。状态：首轮对照已实现，长期核心去留证据仍不足。

## 决定

保留独立核心，不将 Deep Agents 或 Pydantic AI 安装到生产核心环境。两个上游分别使用固定包版本和锁文件，由独立工作进程执行；比较代码位于 benchmarks，生产应用不导入它。

比较分为原生正例与共同宿主组合。正例必须实际调用各自 agent loop、实际工具、原生审批与持久状态；每次动作使用独立进程。共同宿主用独立 SQLite 业务台账验证当前权限/版本、稳定请求、精确审批参数、重复写入、取消和结果核对。该宿主属于实验集成代码，不是发布的身份服务。

共同宿主产生的保障统一归于宿主，不作为某个运行时的原生收益。原生六类故障矩阵未完成，独立接入者及真实业务条件尚未具备，当前架构结论为“证据不足”，不得写为胜出或上游不具备能力。因此暂停扩大核心，继续维护现有工程边界和补测入口。

## 故障与证据

写入落地后使用实际进程退出制造回执丢失；下一进程以业务台账核对，不猜测执行是否完成。此路径可把宿主结果置为成功，但不代表原生框架检查点已自动修复，原生运行仍需其适配器另行核对。

取消分别发生在写入前与提交后。异常的框架包装由适配器转换，已有业务效果不被“取消”等同为回滚。初版取消适配失败须保留，修复后重跑，不将本地误配置归为上游缺陷。

模型为确定性 fixture；记录实际输入而非伪造真实 token。运行资料全部合成，不调用远程模型、不读取业务封存正文。真实资料和密钥将来的存储需遵循下一阶段计划的受控证据边界。

## 替代方案与局限

不以自写轻量适配器代表上游全部能力；不把共同宿主代码的通过率当作原生运行时安全得分。未实现的原生矩阵明确记录未测。当前对照不能支撑真实模型质量、生产隔离、分布式恢复、开发者工时或成本收益结论。
