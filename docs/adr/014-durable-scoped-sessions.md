# ADR 014：持久会话与当前授权分离

Date: 2026-10-14. Status: implemented for the 0.4.0 candidate.
日期：2026-10-14。状态：0.4.0 候选已实现。资格以
`reports/session-release-audit.json` 与冻结源码证据为准，本 ADR 本身不作为通过证据。

## 背景

下一阶段计划 S1 要求两个业务共用多轮会话、审批和恢复。旧 knowledge
会话没有 application/tenant/actor/resource 绑定，普通聊天绕过 Harness，
不能仅重命名为公共模块。Harness 则已经持久化精确的 RunContext；包括角色、
correlation_id 在内的旧执行身份不能被每次 HTTP 请求的新身份覆盖。

## 决定

1. 新建可嵌入的 SessionService，接受注册的 ApplicationSpec 或 WorkflowSpec。
   SQLite 保存会话、顺序轮次、稳定请求键和运行关联；通过公开 Harness 与
   WorkflowRunner 执行、查询、审批、恢复与删除，不读取其内部表。
   可选 HTTP router 单独导入 FastAPI，基础 SDK 不依赖 Web 或旧 knowledge。
2. 会话固定应用及策略版本、租户、owner、资源与工作区。每个公共操作必须调用
   宿主授权函数，输入是本次认证的 RunContext。HTTP 内容只包含任务参数，不能
   提供角色、租户或工作路径。宿主负责查验登录身份和当前资源权限；应用工具策略
   在每次副作用前继续检查当前权限。没有内建账号系统或公网身份认证声明。
3. 每轮生成稳定运行 ID，保存原执行 binding。恢复先校验当前权限和绑定兼容性，
   再使用原 binding 调用原运行。角色变化时保守拒绝恢复，不将新角色注入旧审批。
   委托审批分别接收新认证的 owner 与 approver，不能由申请消息伪造。
4. 每会话单写者：跨进程非阻塞文件锁覆盖操作，事务内登记轮次，数据库事务不跨
   模型 await。相同请求键与相同清洗后内容返回已有轮次，内容冲突拒绝。挂起轮次
   未解决前不接受下一轮。崩溃后使用稳定 run ID 对账：已有完成证据同步回来；
   未开始的轮次可以开始；无法确认的状态不虚报成功。
5. 历史作为带来源版本的不可信 ContextMaterial 进入现有预算编译器。仅成功轮次
   可进入模型上下文；模型实际输入仍以 model.request trace 为准，历史不是可信
   长期记忆。外部资料 provider 必须配套宿主当前材料校验器；读取、输入、恢复前
   检查版本/撤回/权限。历史衍生依赖不能因转换成文本而丢失。
6. 会话持久化前应用 EvidenceTransform，与模型及运行证据相同。保留删除墓碑，
   禁止恢复已删证据。删除必须涵盖会话文本副本及所依赖的运行证据；历史中的派生
   内容也必须受失效检查。物理备份、外部附件、领域 PII 和保留期限仍由宿主管理。
7. 关闭禁止新提交；活动轮次的关闭行为由服务明确拒绝，避免关闭后仍发生隐藏写入。
   失败、耗尽、待审批与成功分别记录。消息长度、历史窗口和事件分页有界。

## 验证与未覆盖范围

决定 1–7 的确定性证据：服务级契约见 `tests/unit/test_sessions.py`（绑定与跨租户
拒绝、上下文提供者记录与失效、有界历史、单写者与挂起轮次、workflow 会话、墓碑与
会话退役、关闭语义、崩溃窗口对账、未开始轮次不得虚报）；HTTP 适配层与身份再认证
见 `tests/unit/test_session_control.py`；两条业务会话、重启、撤权与委托审批的
可执行示例见 `examples/session_demo.py`；候选冻结、干净副本复验、构建与最小安装见
`benchmarks/session_verification.py` 及其自身回归测试。

未覆盖：真实模型的多轮质量、真实宿主 IAM 与跨主机并发、旧 knowledge 数据迁移、
分布式 lease 或 outbox，以及任何法律/电商业务结论。这些不属于本 ADR 的通过范围。

## 后果与替代方案

不修改旧会话表，避免把旧数据默认为已授权的新会话。代价是没有自动旧数据迁移；
迁移需要宿主补足身份与来源，作为后续独立变更。单机 POSIX/SQLite 保持现有边界，
不引入分布式 lease、通用后台队列或跨数据库事务。权限/材料失效时拒绝读取或恢复
会降低可用性，但不会用过期快照替代当前授权。

首轮只验证合成法律/电商会话与确定性模型，不证明真实业务质量。FH-015–018
保持历史开放状态。0.3.0 冻结记录保留，新候选重新做审查、完整门禁、干净快照复验
及最小 wheel 安装。具体接口、结果和限制以 S1 文档及候选审计为准。
