# ADR 039：SaaS 首批身份接线与状态迁移边界

- 日期：2026-10-28
- 状态：已采纳首批实施边界；PostgreSQL 运行后端尚未实现/验收
- 关联：[SaaS 总计划 v3](../archive/SAAS_PRODUCTION_MASTER_PLAN_V3_2026-10-28.md)、[ADR 038](038-application-identity-boundary.md)、[状态事务契约](../guides/SAAS_STATE_CONTRACT.md)

## 背景

0.9.2 的工程资格绑定历史源码。当前身份层已有真实账户、邀请、撤权与独立审批凭据，但演示入口仍使用公开角色名。SDK 会话、审批、调用账本、R2 与 provider 容量直接依赖本地 SQLite/文件锁。knowledge 的 PostgreSQL 会话存储不包含 SDK 的这些事务，不能作为跨机器接管已完成的证明。

## 决策

1. 新增独立邀请制工作台入口，复用现有身份和 SessionService/Harness；公开角色演示继续只承担其合成测试职责。
2. HTTP 认证后，运行时仍通过可信绑定中的 user/workspace 查询当前成员；凭据不得进入 RunContext、模型输入、trace 或报告。公开 current_principal 仅供可信宿主使用，不作为认证 API。
3. 成员管理以当前数据库权限为准，在写入事务内重新检查，不能相信先前 Principal 的角色快照。工作空间管理员只能改变本工作空间的成员，不可禁用共享用户在其他工作空间的账户或凭据。
4. 真实身份工作台的 app/policy 版本独立于旧 demo；旧身份绑定和审批不跨应用隐式接管。
5. 首批工作台仍为本地 SQLite、确定性咨询模型；PG 集群、OIDC、真实业务与商业收费维持未实现状态。
6. SaaS 状态仓储按操作级原子事务设计，不先机械替换 SQL 连接。第一 PG 切片独立验证受理/幂等/outbox/租约/调用预留与回执，再逐步接入执行器。
7. PG 试验只能在新建隔离数据库/实例中执行，禁止在现有商家数据库上自动建表、启停其服务或改变凭据。
8. 新工作台状态在空目录 bootstrap 时写入应用绑定标记；备份摘要与标记必须一致。旧未标记状态按历史 consultation 处理，不能自动采用工作台身份。

## 多节点必须保持的语义

- epoch 防止旧 owner 写运行投影，但不能撤销已发送的外部请求；发送边界必须配合外部幂等和可信查询。
- worker 死亡/租约过期不是 provider 结束证据；unknown 调用的预算与物理容量不因接管自动释放。
- 旧 owner 的迟到结果不能直接覆盖运行，但实际回执和用量仍须进入独立去重收据账本，由当前 owner/可信核对器裁决。
- 审批消费、预算预留、调用准入与可提交的状态变更在同一个事务中完成。
- trace 对象与数据库清单通过不可变内容摘要/提交状态协调；缺失证据不得被显示为可重建。

## 后果

首批可交付一个经真实账户保护的本地工作台和回归证据。它不构成 M1 全部通过；M0 中客户、地区、预算与责任待输入，M1 的 PG/多节点门禁需真实环境。每次发布仍需新候选、完整质量门禁、审查与干净副本复验。
