# ADR 032：编排对照与宿主证据的边界

日期：2026-10-26。状态：采用；正式模型对照仍取决于开发基线和运行条件。

求职改进 F1–F5 复用现有 Harness、RunKernel、R2 故障测试、hash-chained trace 和
`benchmarks.comparison.verify` 冻结驱动，不增加运行时或另建评测平台。

策略对照 A 为单 ReAct，B 为固定材料读取加一次模型综合，C 为 planner 选择材料读取顺序、
worker 综合、reviewer 复核。所有调用经相同预算机制；C 三角色均计费。当前 kernel 串行
调用，故不检验并行吞吐收益。任务是人工编写的短小合成开发诊断题，不是代码修复、
独立业务终评或第三方 benchmark。12 题开发集与 30 题评价集不共用题目模板；
作者在构造时看过题目和答案，不称从未见过的独立 holdout。

先完成开发模型基线，再封存模型、脚本、题集、预算、重复次数与决策阈值。
正式运行要求冻结协议身份匹配。每次运行保存结果和 trace；全部失败留在分母，
基础设施故障使策略测量失效，不将 HTTP 错误当作模型能力。重采样以 task 为聚类单位。
本机 tokens 作为资源消耗，API 无付费不等于硬件/电力成本为零。

F1 静态检查宿主精确 wheel 摘要、SDK facade 导出和显式 import；不把静态检查称为运行兼容。
宿主测试使用各自已锁定版本和独立进程，数据/缓存/报告定向到当前工作区；不修改宿主源码、
绑定或真实数据。不复制私有宿主源码到框架 trace。代码身份仅记录摘要。

F3 将六组既有契约各在三个独立 pytest 进程重复，保存 SQLite、trace、JUnit 和文件摘要。
合成外部回执不证明真实商家/法律系统。额外 ForgeCommerce drill 在实际 HTTP ASGI 入口
执行本地测试租户工单，并在 SDK 成功、宿主投影前 `os._exit`，新进程对账。
ASGI 入口测试不等于真实 TCP、UI 或生产集成。

独立接入记录只能由未读源码的真人产生；无人参与时仅记录作者自测。
原生框架完整故障比较、分布式调度、HA 和外部 exactly-once 继续不在已证实范围。
