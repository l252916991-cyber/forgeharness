# PostgreSQL 托管串行执行

更新：2026-11-01。状态：0.12.0 候选已实现；工程资格以[本次报告](../reports/saas/20261030-hosted/REPORT.md)为准，
不是完整 SaaS 上线签收。历史 [0.11.0](../reports/saas/20261029-state/REPORT.md)仅认证其冻结范围。

`forgeharness.cloud.runtime.HostedRuntime` 把现有串行 `AgentRuntime` 接入唯一的
PostgreSQL 状态权威。它没有在 PG 租约外再包一个 SQLite Harness，也不另写模型循环。
普通成员、独立审批成员和执行服务成员分别使用当前数据库权限。

## 接入契约

宿主配置 `PostgresRunStore`，通过 `HostedApplication` 注册可信 `ApplicationSpec`、
发行物摘要、模型账户/配置摘要、每次模型/工具的单位预留，以及独立的结果核验器。
这些配置来自部署代码，客户请求不能传入 Python 导入路径或选择任意实现。
`TenantContext` 由已认证的宿主生成；这个内部服务接口本身不提供通用登录认证。

控制器支持：

- `accept`：相同幂等键和完整绑定返回同一运行；更改输入或部署绑定产生冲突。
- `inspect`、`trace`：按当前组织/成员和 owner 范围读取完整 checkpoint、结果和有序证据。
- `approve`：仅当前独立审批人能批准精确的规范工具参数；普通 owner 无法自批。
- `advance`：仅执行服务能认领租约、核账、运行或恢复；租约 epoch 隔离旧工作进程。
- `cancel`：持久取消意图；已发生的外部操作继续核账，不声称撤回。

模型调用使用现有准备与派发路径，工具调用使用现有注册表、策略和分发器。
工具收到数据库规范幂等键。上下文资料在首次执行时检查组织、应用、资源和有效期，
将版本、选择决定及精确模型输入持久化；审批恢复沿用已提交的 transcript。
发行物摘要必须覆盖适配器、策略、资料提供器和验证器实现；类型名不是实现内容摘要。

## 发送、恢复和用量

调用准入将精确审批消费、各维用量预留、物理调用身份、checkpoint 和证据纳入事务。
发送许可持久化后才调用外部适配器；结果必须由可信提供商/业务账本独立核实。
完整结果、不可变收据、实际用量和预留释放均持久化。成功还需要应用终验。

响应丢失、缺失可信用量、超时和租约失效都不等于未执行。原调用的预留保持，
下一工作进程查询可信 resolver，重用原结果；不能确认则继续待核账，不重新派发。
旧 epoch 可以追加真实结果事实，不能覆盖当前控制状态。
只有仍处于 admitted、从未取得发送许可的旧 epoch 调用，才能在当前租约事务内
生成明确的未发送证明、释放预留并结束原运行；重试须另建新运行。

策略拒绝、未知工具和参数无效属于确定性的逻辑请求用量，消耗工具调用次数，
不制造模型/工具收据或供应商费用。逻辑用量与物理结果分别存事实，保存时共同对账。
单位预留不等于人民币。组织月额度、价格版本和真实模型账单核对仍需后续实现，
因此当前不能宣称已强制执行用户确认的每月 1000 元总预算。

## 支持边界与验证

当前为可信、无物理工作区、单次物理尝试的串行应用。R2、并行、嵌套调用、
会话、自动重试、共享 provider 容量和公平调度尚未迁移到这个后端。
组织开通/通用身份/API/UI、资料生命周期、账单、支付与云端运维仍是总计划的一部分。
用户已有服务器和模型服务，后续通过本机配置接入；本轮没有连接这些资源或调用收费模型。

开发测试使用临时真实 PostgreSQL 18.6、两个应用和独立合成业务账本，覆盖审批、
真实副作用、响应丢失、跨 Python 进程恢复、旧工作进程接管、撤权、取消和结果终验。
另用随机回环端口的真实 HTTP 服务验证 `OpenAICompatibleModel` 的实际请求和用量。
显式缓存标记在预检前纳入完整发送快照，三个缓存模式均逐字节核对实际请求。
HTTP 响应在解析前受字节上限和完整请求时限约束；适配器请求 `identity` 编码，
拒绝其它内容编码，避免预先解压绕过上限。过大响应和连续慢响应保持待核账，
不会伪造零费用或重新派发。
这些是本地工程证据，不是业务质量、互联网身份安全或云端持续运行证明。
