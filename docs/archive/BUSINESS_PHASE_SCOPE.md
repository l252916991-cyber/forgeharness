## 需求与复用映射

| 需求（计划书） | 复用 | 本轮新增与可观察结果 |
| --- | --- | --- |
| S2 暂存→校验→审核→发布→可检索 | `RevisionStore`（草稿/CAS/独立审核/发布/撤回）、`SourceAnchor` | `sdk/imports.py` 暂存区与导入编排；每条导入有稳定业务键与校验结论 |

| S2 持久任务、进度、重启恢复、取消 | 调用日志状态机、`RecoveryCoordinator` 形状 | `sdk/tasks.py`：`queued/running/succeeded/failed/cancelled/needs_reconciliation` |
| S2 取消语义：停未开始、已执行需核对、不等于回滚 | `decide_retry`、`InvocationState` | 未开始可直接取消；运行中请求只置标记，保留实际结果，不声称回滚 |
| S2 重试按动作能力、稳定业务键 | `decide_retry`、`idempotency_key_for` | 重试复用同一任务身份与业务键，不产生第二份资料/索引 |
| S2 临时文件/解析结果/索引/运行证据保留关系 | `RevisionStore.delete`、`Harness.delete` | `RetentionPolicy` + 有界清理；非终态任务的证据不被清理 |
| S2 任务状态页 | `session_router` 模式 | 可选任务 API 与状态页；宿主负责创建和运行任务 |
| S3 案件适配器与页级原文定位 | `Citation`/`CitedAnswer`/`CitationVerifier`、`SourceAnchor` | `applications/legal/adapter.py` 合成案件适配器；引用定位到页/段落 |
| S3 只读问答 + 待审笔记 | `cited_draft_workflow`、`RevisionStore.review` | 只读问答应用、缺证据拒答、笔记草稿进入独立审核 |
| S3 与原有流程对照、接入与回退 | 现有单点发布读取流程 | `reports/legal-pilot-comparison.json` 合成原文对照；真实 LexVault 同题对照待接入 |
| S4 商品与知识导入、审核 | S2 导入链 + `RevisionStore` | 商品目录/FAQ 导入适配器、失败清单、独立审核 |
| S4 多轮咨询、实时价格库存 | `SessionService`、`CommerceStore` | 咨询应用：结构化比较、沿用上一轮商品、带来源回答；自然语言澄清待评测 |
| S4 人工转接与工单 | `create_handoff` 幂等台账 | 有商品时处理冲突/明确要求转接；无商品时提示人工帮助，通用工单待实现 |

## 角色、资料与数据流

法律：合成案件拥有者、独立复核者（`reviewer`/`publisher`）、另一案件或租户的无权用户。
资料仅为仓库内的合成案件文本与页级锚点，不读取 LexVault 或真实案卷。
电商：合成商家 `shop-a` 拥有者、隔离验证租户 `shop-b`、消费者角色；资料为合成商品目录
（30–50 个 SKU）与 20–30 份带来源的说明/FAQ，以及模拟价格库存接口，不接真实店铺。

数据流：宿主认证 → 当前资源授权 → 暂存 → 解析/校验（任务）→ 草稿 → 人工审核 →
发布 → 建索引；咨询/问答 → 授权候选检索 → 版本与权限再校验 → 带来源回答 →
（无证据/冲突/要求人工）转接工单；一切读取都以当次身份与当前版本为准。

## 完整验收脚本

| 步骤 | 命令/场景 | 预期 |
| --- | --- | --- |
| 1 | 导入合成资料（合法内容） | 暂存→校验→草稿，业务键幂等，重复导入不新建版本 |
| 2 | 人工审核并发布 | 未审核不可检索；发布后检索可见并带版本 |
| 3 | 撤回或发布新版本后检索旧内容 | 旧内容不再出现；陈旧索引行被清理 |
| 4 | 越权检索（另一租户/未授权资源） | 打分前即无候选；不泄露命中数 |
| 5 | 解析任务中途取消 | 未开始的工作不执行；已执行写入进入待核对；不报“已撤销” |
| 6 | 可重试失败（超时） | 同一任务身份重试；不产生第二份资料或索引行 |
| 7 | 不可重试失败与不确定结果 | 分别落为 `failed` 与 `needs_reconciliation`；重启后需宿主核对 |
| 8 | 进程重启后继续 | 非终态任务可枚举；完成的任务不重跑，故障重试可能重新解析但不重复创建资料 |
| 9 | 法律案件只读问答 | 回答带页级引用；缺证据时不虚构来源 |
| 10 | 资料变更后读取旧笔记/历史 | 拒绝返回并使旧笔记失效；提示重建会话 |
| 11 | 电商多轮咨询与比较 | 追问、比较成立；价格库存带查询时点 |
| 12 | 无证据/冲突/要求人工 | 有商品时按策略转接，工单含上下文与证据；无商品仅提示需人工 |
| 13 | 工单创建后重试或恢复 | 不产生重复工单；状态可查 |
| 14 | 封存集治理 | 未冻结目标前拒绝运行封存集；冻结后才允许，并记录声明时间早于运行时间 |
| 15 | 候选发布 | 冻结清单、干净副本复验、wheel/sdist 成员与最小安装全部通过 |

以可执行测试、清单与报告为准；表格不替代通过证据。

## 持久化与迁移边界

新增 `sdk/tasks.py`、`sdk/imports.py`、`sdk/retrieval.py` 各自使用独立 schema version
（均以 1 起始），不修改旧 knowledge 表，不迁移旧资料。会话、记录、工作流与执行证据的
既有 schema 不变。版本上调至 0.5.0 候选后重建锁文件中的项目元数据，无意变更依赖版本。
S2–S4 保持本地可信宿主模型；真实外部写入需要另行设计核对能力，本轮不承诺 exactly-once。
来源撤回采取拒绝策略，不自动生成未经评估的替代摘要。
