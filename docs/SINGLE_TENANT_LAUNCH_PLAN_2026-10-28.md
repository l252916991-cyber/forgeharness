# 单租户生产上线执行计划（一个真实业务）

> 2026-10-28 最新最终目标见 [SaaS 总计划 v3](SAAS_PRODUCTION_MASTER_PLAN_V3_2026-10-28.md)。本文保留为中间业务试点的工作包参考；以下“最终目标/不做”边界仅适用于本单租户阶段，不再限制完整 SaaS 路线。

编制日期：2026-10-28 ｜ 状态：执行计划 ｜ 目标形态：**生产级单租户，一个真实业务上线**

本文件是从 [通用生产级 SaaS 计划书](SAAS_PRODUCTION_PLAN_2026-10-28.md)（v2）裁剪出的执行路径。选择理由：只有一个业务、一个组织、不需要对外收费、不需要 24×7 合同承诺，因此六个谓词里 P1、P2、P4 整段不需要，P3/P5/P6 降级保留。

**这不是 SaaS。** 本文件不产生任何多租户、计费或 SLA 承诺；v2 保留为“若日后出现第二个互不知情的组织”的档案，不删除、不修改。

## 0. 一页结论

| 项 | 结论 |
| --- | --- |
| 交付物 | 一套可独立运行、可备份恢复、可定位故障的咨询与人工服务系统 |
| 用户 | 3–20 名内部用户（咨询用户、客服、审批人、知识编辑/发布、管理员） |
| 部署 | 单机 POSIX / Python 3.12 / SQLite / 单入口 HTTPS，1 个 API 进程 |
| 规模上限 | ≤30 并发会话、≤5k 轮次/日、≤5GB 库；**超限触发评估，不自动扩容** |
| 真实模型 | 1 个 provider、≤2 个档位（主 + 降级），参数与预算冻结 |
| 工作量 | **92–122 有效人日**，全职约 20–24 周 |
| 上线判据 | 下文 10 条退出条件，全部可复核；不看页面数 |
| 最大风险 | 模型质量不达标；真实数据授权；单人运维 |

## 1. 退出条件（唯一的“完成”定义）

十条全绿才算上线。任一条不成立，就还是“参考应用”。

| # | 条件 | 复核方式 |
| --- | --- | --- |
| 1 | 真实用户用自己账户登录，无演示角色；两名同角色用户 `actor.id` 不同 | 登录两人，查审计中的 actor |
| 2 | 撤权或禁用后，下一次请求即被拒 | 禁用后立即调用接口，观察 401 |
| 3 | 一次真实咨询：价格/库存来自工具，回答带可打开来源，来源版本与时间可见 | 现场演示 + trace |
| 4 | 无证据时澄清或建议转人工；评估集 30 题中 0 条无依据结论 | 评估记录 + 失败样本 |
| 5 | 用户确认 → 待审批 → 独立审批人批准 → 恰好一张工单；自批被拒 | 端到端用例 |
| 6 | 客服领取、处理、解决；并发领取只有一个成功；用户能看到结果 | 双客服并发测试 |
| 7 | 知识草稿 → 审核 → 发布 → 新咨询使用新版本；撤回后新咨询不再使用 | 版本与撤回用例 |
| 8 | 刷新/断网/重启不产生第二张工单；待审批重启后仍待审批 | 故障注入 |
| 9 | 备份 → 恢复演练一次，记录实测 RTO/RPO；恢复后历史、审批、工单、trace 一致 | 演练报告 |
| 10 | 一次真实故障被告警发现并按 runbook 处理，有复盘记录 | 告警记录 + 复盘 |

第 10 条要求“真实发生”，不能用演练替代演练之外的演示。

## 2. 明确不做（附理由，便于日后拒绝需求）

| 不做 | 理由 |
| --- | --- |
| 多租户 / RLS / 每租户密钥 | 只有一个组织；引入隔离层只增加成本与故障面 |
| 计费、账本、发票、套餐 | 不对外收费；内部结算不需要计量管道 |
| SSO / SAML / SCIM | 3–20 人规模，邀请制账户足够；已实现的密码+令牌+撤权路径可用 |
| 跨区 / 多 AZ / K8s | 单机业务；高可用成本远高于停机损失（按 2h RTO 计） |
| SLA 条款与信用 | 内部系统，承诺“工作时间支持 + 2h 响应”即可，写入运维手册 |
| Postgres 迁移 / Store 协议化 | SQLite 在容量上限内足够；**本路径不动 SDK 状态层** |
| 第二打包应用 | 通用性证明只对 SaaS 有意义 |
| 移动端、多语言、多模态、可视编排 | 与主链路无关 |

新增需求必须回答：它让十条退出条件中的哪一条变绿。答不出就进“上线后评估”。

## 3. 架构（单机，明确上限）

```
浏览器
  → Caddy/nginx（TLS、访问范围、请求体大小、超时）
  → API 进程 ×1（uvicorn --workers 1，FastAPI）
      ├─ identity_http：登录/退出/邀请/审批/依赖注入
      ├─ 咨询/工单/知识/运行诊断接口
      └─ SessionService[Harness] → SQLite(WAL) + trace/checkpoint 目录
  → 模型 provider（HTTPS，超时 + 重试 1 次 + 降级档）
  → 告警出口（邮件/webhook）
```

| 决策 | 选择 | 说明 |
| --- | --- | --- |
| 进程模型 | 1 API 进程，`--workers 1` | 多进程写同一 SQLite 不作为扩展手段 |
| 异步 | 进程内 async | 长任务用现有 TaskStore 路径，不引入队列 |
| 存储 | SQLite WAL + 本地磁盘 | 单写者；容量上限见下表 |
| 状态目录 | `0700`，固定绝对路径 | 沿用既有互斥锁与权限要求 |
| 反代 | Caddy 或 nginx，TLS 终止 | 只监听内网/回环 + 白名单 |
| 配置 | 环境变量 + `.env`，缺关键项拒绝启动 | 禁止默认密码与默认密钥 |

**容量上限与触发线**（超线先评估，不自动扩容）：

| 指标 | 上限 | 触发动作 |
| --- | --- | --- |
| 并发会话 | 30 | 观察 p95；连续 1 周超限 → 评估垂直扩容 |
| 轮次/日 | 5,000 | 同上；超 8,000 评估迁 PG |
| 数据库 | 5 GB | 超 4 GB 启动清理/归档评估 |
| 单轮 p95 | ≤8s（工具密集型 ≤20s） | 超限先查模型耗时占比 |
| 磁盘余量 | ≥20% | 告警 |

## 4. 真实依赖接入

| 依赖 | 本路径做法 | 不做什么 |
| --- | --- | --- |
| 身份 | 用已实现的 `identity.py`：邀请制账户、scrypt 密码、SHA-256 令牌、禁用即时生效；把 `identity_http` 挂到应用入口 | 不接 IdP/SSO |
| 模型 | 一个 provider，主档 + 降级档；冻结 temperature、max_tokens、timeout、重试次数 | 不做多 provider 路由与灰度 |
| 商品/FAQ | 自建目录（30–80 商品 / 50–150 FAQ / 3–5 条政策），带来源、版本、生效时间 | 不接商家实时接口（除非已有授权） |
| 工单 | 本地 SQLite 工单，补 `requester_id`/`assignee_id`/`resolution`/`version` | 不接外部渠道 |
| 用量 | 本地表记录 tokens、耗时、失败与重试，供月报 | 不做账本与发票 |

数据授权优先级：授权真实资料 > 自建目录（明确标注“自建”）> 合成数据（仅测试）。**任何情况下不把合成数据说成真实商家数据。**

## 5. 模型接入的具体边界

分两步，第一步先上线，第二步视质量再开：

| 步 | 模型职责 | 系统职责 | 上线判据 |
| --- | --- | --- | --- |
| 一 | 理解问题、选工具、选对象、判断是否澄清 | 校验参数、执行权限与审批、取得真实事实、展示确定性的价格/库存/来源/工单状态 | 评估集通过，且最终回答中的事实字段全部来自工具 |
| 二 | 在事实之上生成自然语言总结 | 结构校验 + 引用存在性 + 数值一致性 + 抽检 | 引用有效率 100%，无捏造工单/订单状态 |

失败处理：超时或格式错 → 重试 1 次 → 明确失败提示并保留 run 记录；**不降级成“看起来成功”的回答**。预算：单次运行上限 + 日总量上限，超限拒绝新任务并告警。

## 6. 工作分解（92–122 人日）

| 包 | 内容 | 人日 |
| --- | --- | ---: |
| W1 身份与基线 | 挂载 `identity_http`、登录/邀请/退出页、撤权验证、审计导出；**集成套件可运行** | 8–10 |
| W2 请求生命周期 | 一次业务意图一个 `request_id`、防重复提交、刷新/断网复用、未知结果查询入口 | 6–8 |
| W3 真实模型 | provider 接入、参数与预算冻结、输出契约、失败降级、trace 记录模型与提示词版本 | 14–18 |
| W4 数据与知识 | 字段契约、CSV/JSON 导入 + 校验失败清单、草稿→审核→发布→撤回、影响面查询 | 12–16 |
| W5 工单闭环 | 表结构补齐、状态机与乐观锁、领取/处理/解决接口、SLA 计时、客服台后端 | 14–18 |
| W6 前端工作台 | 登录、咨询、工单进度、客服台、审批台、知识与发布、运行诊断/用量，共 7 页最小可用 | 16–22 |
| W7 部署与运维 | 单机部署脚本、TLS、systemd/容器、live/ready/依赖三层探针、结构化日志、告警、5 篇 runbook、备份 + WAL 归档 | 10–14 |
| W8 验证与上线 | 集成/E2E、评估集（开发 40 + 终评 40）、6 项故障演练、恢复演练、真实用户试用、上线检查 | 12–16 |
| **合计** | | **92–122** |

全职（20 人日/月）约 4.6–6.1 个月。关键路径：W1 → W3 → W5 → W6 → W8。

| 阶段 | 交付 | 退出 |
| --- | --- | --- |
| 第 1–3 周 | W1 + W2 | 真实登录可用，重复提交不产生第二次业务 |
| 第 4–7 周 | W3 + W4 | 真实模型跑通有来源回答，资料可发布/撤回 |
| 第 8–11 周 | W5 + W6 主体 | 工单能从创建走到解决，页面可用 |
| 第 12–15 周 | W6 完成 + W7 | 目标机器独立运行，告警与备份就绪 |
| 第 16–20 周 | W8 | 十条退出条件全绿 |

## 7. 验证清单（可逐条打勾）

| 类型 | 项 |
| --- | --- |
| 集成 | 认证→会话→执行→审批→工单→恢复全链路；当前集成套件**未运行**，必须恢复 |
| E2E | 登录隔离、无证据不编造、确认后待审批、自批被拒、审批后仅一单、重复点击不重复建单、客服领取与解决、刷新恢复 |
| 评估 | 开发 40 题 + 终评 40 题（冻结后只用一次）；事实正确率 ≥95%、引用 100%、澄清/转人工 ≥95% |
| 故障 | 模型超时、provider 5xx、磁盘满、进程被杀、待审批重启、SQLite 锁竞争 |
| 恢复 | 全量恢复 + 待审批中恢复；记录实测 RTO/RPO |
| 安全 | 越权（会话/工单/来源）、CSRF、过期 Cookie、撤权后重放、body 断言身份 |

固定门槛：越权 0、未审批副作用 0、重复业务副作用 0、虚假完成 0、伪造引用 0。

## 8. 运维承诺（替代 SLA 条款）

| 项 | 内容 |
| --- | --- |
| 支持时间 | 工作日 09:00–19:00；非工作时间的故障次日处理 |
| 响应 | P1 2h、P2 1 工作日、P3 3 工作日 |
| 维护窗口 | 提前 24h 通知，单次 ≤30min |
| 备份 | 每日全量 + 每 15min WAL 归档到第二位置；RPO ≤15min |
| 恢复目标 | RTO ≤2h（人工介入），RPO ≤15min；以演练实测值对外 |
| 告警出口 | 邮件 + 一个即时通道；就绪探针失败、错误率超阈、磁盘不足、备份失败 |
| 事故 | 发现 → 告知 → 止血 → 复盘（5 工作日内）；复盘只写事实与行动项 |

## 9. 风险与触发线

| 风险 | 触发信号 | 应对 |
| --- | --- | --- |
| 模型质量不达标 | 终评事实正确率 <95% | 退到“只陈述工具事实 + 模板化表达”，不硬上自然语言总结 |
| 真实数据拿不到授权 | 授权文件缺失 | 用自建目录并明确标注数据来源与范围 |
| SQLite 容量/写竞争 | 库 >4GB 或锁等待告警 | 评估迁 PG（届时才动 Store 协议） |
| 单人运维 | 夜间故障无人处理 | 承诺只到工作时间；关键告警加短信 |
| 范围蔓延 | 出现“顺便加个…”需求 | 只认十条退出条件；其余进上线后清单 |
| 集成套件长期不跑 | CI 只有单元测试 | W1 必须让它跑起来，否则后续全凭人工 |

## 11. 与 v2 的关系

| v2 谓词 | 本路径处置 |
| --- | --- |
| P1 同一套代码 | 暂缓（无第二组织；单机即只有一份代码在跑） |
| P2 同时服务多个 | 暂缓（改为单机容量上限与触发线） |
| P3 互不知情 | 降级为“内部多用户对象级隔离”：会话/工单/来源越权为 0，无需 RLS 与租户密钥 |
| P4 能收钱 | 暂缓（不做计量管道，只记用量供月报） |
| P5 能承诺 SLA | 降级为 SLO + 告警 + 工作时间支持，无合同条款与信用 |
| P6 能恢复 | 保留：单机备份 + WAL 归档 + 实测 RTO/RPO + 恢复演练 |
| 通用性证明 | 暂缓（不宣称通用平台） |

v2 的 24 条证据中，本路径需要 6 条（9、10 的部分、14、17 的简化版、23、24），其余标记 N/A 并附理由，避免日后被“你计划里有 24 条”追问时口径混乱。
